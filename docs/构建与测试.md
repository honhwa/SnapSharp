## 1. 开发与运行环境

- Windows 10 2004 及以上或 Windows 11；WPF、Per-Monitor V2 DPI 感知。
- 构建使用 .NET 10 SDK；依赖框架的构建版运行需要匹配的 .NET 10 Desktop Runtime，自包含发布版已带运行时。
- 当前主程序固定 x64，录屏组件需要 Microsoft Visual C++ Redistributable x64 及 Windows Media Foundation。Windows N/KN 需 Media Feature Pack，Server 需相应媒体组件。
- OCR／抠图模型不随程序分发；Windows OCR 依赖系统语言包，摄像头与麦克风依赖系统权限。

## 2. 目录约定

| 路径 | 职责 |
|---|---|
| 仓库根目录、`Views`、`Services` | 主程序及跨模块编排 |
| `Libraries` | 功能类库、插件契约、插件宿主和新增插件项目 |
| `docs` | 使用、开发及产品文档 |
| `obj` | 编译中间文件，不是发布物；构建时会重新生成 |
| `bin\Release` | 下方显式 `-o` 构建命令的输出目录 |
| `.artifacts\publish\win-x64\时间戳` | `publish.bat` 生成的独立自包含发布目录 |

开发构建与发布目录分开：下方构建命令显式输出到 `bin\Release`；发布脚本每次生成新的时间戳目录。未指定 `-o` 的构建仍按项目默认规则输出，不能假定所有构建均进入 `bin\Release`。各项目会生成正常的 `obj` 中间文件，不要为整理发布物删除源码、模型或未知目录。

## 3. 构建

在仓库根目录执行。若目标目录下程序正在运行，先停止录屏、处理未保存内容，再通过托盘正常退出，避免 DLL 占用。

```powershell
dotnet restore .\NimCap.Screenshot.csproj
dotnet build .\NimCap.Screenshot.csproj -c Release --no-restore -o .\bin\Release -m:1 /p:UseSharedCompilation=false
```

`--no-restore` 仅在依赖已还原时使用。网络还原可能需要代理或网络许可；不要把依赖下载失败误认为编译错误。运行入口为 `bin\Release\NimCap.Screenshot.exe`，无需为了验证构建自动启动普通托盘实例。

### 一键发布 Windows x64 自包含版

仓库的 `NuGet.Config` 将漏洞审计独立指向 NuGet 官方 `https://data.nuget.org/v3/index.json`，不修改包下载源，也不关闭审计。构建机需要允许访问该端点及其漏洞数据文件。若出现 `NU1900`，检查网络、代理和证书后重新还原；不要通过忽略警告或关闭审计来代替修复网络连接。

在项目根目录双击 `publish.bat`，或在命令行执行：

```powershell
.\publish.bat --no-pause
```

脚本使用 Release、`win-x64`、`--self-contained true`，不启用单文件合并或裁剪，输出到 `.artifacts\publish\win-x64\时间戳\`，并附带根 README 和第三方声明。首次发布需要联网还原匹配的运行时及依赖包。

- 目标电脑无需单独安装 .NET Desktop Runtime；原生组件仍可能需要 VC++ x64、Media Foundation 和匹配的显卡驱动。
- 必须分发整个输出目录，不能只复制 `NimCap.Screenshot.exe`。模型权重、用户配置和截图历史不会被打包。
- 不删除旧产物、不结束正在运行的程序，也不自动启动发布版。失败返回非零退出码；双击默认保留窗口，`--no-pause` 适合自动化，`--help` 查看用法。
- 2026-11-15 已实际执行发布脚本成功，检查了 EXE、.NET 运行时、ONNX Runtime、DirectML 及说明文件。发布成功不等于真实大模型／所有 GPU 稳定性通过。

以下自检命令以开发输出 `bin\Release` 为例；测试发布版时，应将可执行文件路径替换为本次发布目录中的 `NimCap.Screenshot.exe`，并核对日志属于本次运行。

## 4. 自动自检

长截图双向拼接专项检查（不操作真实桌面）：

```powershell
dotnet run --project tools/ScrollingChecks/ScrollingChecks.csproj -c Release
```

覆盖上下及左右往返的有符号位移、已采集区域不重复追加、采集循环、工程保存读取和深色发布说明文字匹配，使用逐像素比较验证内容完整性。

连续行匹配专项包含 160／400 像素高视口、1／7／19／73 像素双向移动、仅剩 21 行有效重叠及空白拒绝。实现采用中央行指纹定位并复核像素，保留双向坐标合并；手动模式直接采集选区，避免每帧重建全桌面 WGC 会话。这些合成检查不代表真实页面快速滚动已验收。

手动采集空闲时等待滚轮事件，事件后持续采样至画面稳定：距最近一次输入至少 350ms 且连续 160ms 未变化才休眠，新输入或画面变化会延长观察。完全重复帧不进入匹配队列；确认预览仍强制采集最后一帧。专项检查覆盖延迟绘制、惯性更新、连续输入、稳定休眠与再次唤醒，以及匹配忙碌时继续采样、失去重叠后恢复和取消清理。

2026-11-25 补充真实桌面竖向验收：Windows 10.0.26300、96 DPI，Edge 149.0.4022.69／Chrome 158.0.8127.37 的隔离本地页，通过生产窗口与原生滚轮验证手动下滚、向上回访和扩展、重新采集成功／取消保留、GDI 自动采集至页尾。手动捕获实际使用 WGC；绝对文档行颜色独立确定预期位移与像素并集，输出和工程往返逐像素一致。执行 `dotnet run --project tools/ScrollingChecks -c Release -- --desktop-browser '浏览器完整路径'`，仅在空闲的交互式桌面运行，不与其他 UI 回归并行；无参数回归会重放已保存的真实样本。样本、版本及范围见[竖向样本说明](../tools/ScrollingChecks/Samples/README.md)。固定栏在选区外；Firefox、Electron、Office、动态布局、真实混屏及其他驱动仍未由本次验证覆盖。

控件级截图的回归检查：

```powershell
dotnet run --project tools/RegressionChecks/RegressionChecks.csproj -c Release
```

仅检查录屏类库、线程约定、输入校验、输出重名保护、暂停计时、GIF 往返、合成画面原生 MP4 编码及主程序录屏配置／工具条／环境窗口布局：

```powershell
dotnet run --project tools/RecordingChecks/RecordingChecks.csproj -c Release
```

该专项检查不采集桌面、音频或摄像头；真实设备与实际录屏仍使用下方显式采集自检或人工验收。

覆盖元素模式和 Tab 轮换、父子层级、重复边界过滤、负坐标、迟到／取消／超时响应、窗口回退和原始像素裁剪，并启动临时 WPF／WinForms 测试窗口，验证遮罩下的跨进程控件识别。加上 `-- --browser-elements` 可使用独立临时浏览器配置和本地 HTML 页面验证网页按钮与输入框，不安装扩展、不启用调试端口、不使用用户浏览器资料。详见 `tools/RegressionChecks/README.md`。

界面语言另有 `--localization-self-test` 双语检查，覆盖资源、配置兼容、运行时切换和中英文设置页渲染；命令及新增语言步骤见[界面本地化](本地化.md)。

### 通用自检

诊断文件写入**当前数据目录下的 `Diagnostics`**。数据目录优先由 exe 旁的 `data-location.json` 决定；没有该文件时，只有 exe 目录没有应用数据项、且 `%LocalAppData%\SnapSharp` 存在应用数据项，才使用旧目录，否则使用 exe 所在目录。完整规则见[使用指南](使用指南.md#data-directory)。

下方通用自检和 OCR 模型自检示例按默认 exe 目录设置 `$dataDirectory`；如果使用旧目录或自选目录，请先将该变量改为当前实际数据目录。

```powershell
# 使用旧目录或自选目录时，请将此变量改为当前实际数据目录。
$dataDirectory = (Resolve-Path -LiteralPath '.\bin\Release').Path
$testProcess = Start-Process -FilePath '.\bin\Release\NimCap.Screenshot.exe' -ArgumentList '--self-test' -WindowStyle Hidden -Wait -PassThru
Write-Output "SELF_TEST_EXIT=$($testProcess.ExitCode)"
Get-Content -LiteralPath (Join-Path -Path $dataDirectory -ChildPath 'Diagnostics\self-test.txt') -Encoding utf8
```

以进程退出码 `0` 和诊断文件 `PASS` 同时作为成功依据。自检不是普通启动；不应把“程序能启动”替代功能验证。

当前覆盖范围包括：

- 标注与图像渲染、格式编码、模板、编辑历史、坐标、主题、工具栏、参数窗口与设置布局。
- 贴图真实右键菜单在 100%／150%／200% 下的渲染、左侧无浅色图标栏、统一分隔线，以及动态分组子菜单与勾选标记；预览写入 `theme-PinMenu-*.png`。
- 设置窗口运行时 Per-Monitor V2 检查，以及 100%／125%／150%／175%／200%／250%／300% 对应工作区尺寸与离屏渲染；检查表单最小尺寸、侧栏和保存按钮可达性。离屏测试不替代真实跨显示器 DPI 切换。
- 贴图与分组、热键路由、托盘入口、长截图共用选区确认、取消不采集、负坐标与无标注底图输出、拼接与工程往返；手动采集回调在无变化时保持等待、确认后结束、不调用模拟滚轮驱动，纵／横向手动输入及方向识别、裁剪／接缝修改撤销重做、上下整行／左右整列裁剪、四边累加像素一致性、不能删空以及选区始终连接边缘。自检使用合成帧和输入回调，不操作真实页面。
- 截图取色的七种格式、灰度／黑白边界值、负坐标、放大镜中心像素对齐、复制成功后退出及复制失败不退出。自检注入文本写入回调，不改写系统剪贴板；真实多屏焦点与剪贴板竞争需人工验收。
- 实际 ONNX Runtime 上的合成检测／CTC／蒙版推理，以及字典、透明度、取消和错误检查。
- 长截图采集指示框的四边线和八个圆形锚点，在 100%／125%／150%／200%／250%／300% DPI 下离屏渲染；验证中心透明，以及捕获排除不可用时所有可见像素留在采集区外。实际滚轮穿透、跨屏定位与捕获排除仍需实机验收。
- QR／Code128／EAN13 生成后解码，CSV/XLSX 导出；真实 GTranslate 包配合假 HTTP 验证授权关闭零请求、请求／解析、取消、重定向、限流和响应大小，不向公共翻译服务发送文本。
- 合成 PNG 源的实际 H.264 软件编码、暂停／继续、MP4 尺寸／时长、原生帧序列转 GIF 与 GIF 解码。

识别和录屏自检使用合成内容，不启动真实桌面录屏、麦克风或摄像头，不发送真实业务网络请求。合成测试不证明真实模型精度、设备同步或 60 fps 性能。

### 实时桌面采集自检

```powershell
$captureTest = Start-Process -FilePath '.\bin\Release\NimCap.Screenshot.exe' -ArgumentList '--capture-self-test' -WindowStyle Hidden -Wait -PassThru
Write-Output "CAPTURE_SELF_TEST_EXIT=$($captureTest.ExitCode)"
```

### 真实模型与运行环境验证

以下均为显式执行的专项验证，不包含在通用 `--self-test` 中。方括号表示可选参数，不要原样输入；诊断文件位于 `<数据目录>\diagnostics`。联网测试会下载模型或安装包，但不修改已保存设置。

| 参数（跟在 `NimCap.Screenshot.exe` 后） | 行为与覆盖范围 | 诊断文件 |
|---|---|---|
| `--license-self-test` | 离线检查发布目录的第三方许可、原始声明及映射文件，并在临时目录模拟旧版 OCR、抠图、公式、本地翻译模型目录的许可补齐 | `license-self-test.txt` |
| `--ocr-model-self-test [CPU或DirectML] [GPU编号]` | 默认 CPU、GPU 编号 0；下载固定 PP-OCRv4 包、校验 SHA256、生成字典，实际识别本地生成的中英文图 | `ocr-model-test.txt` |
| `--tesseract-model-self-test [本地字库目录]` | 不给目录时下载中英文字库；给目录时读取 `eng.traineddata` 和 `chi_sim.traineddata`，仍校验固定大小及 SHA256；安装到独立目录，验证真实原生识别、缩放坐标及取消 | `tesseract-model-test.txt` |
| `--specialist-model-self-test [本地模型源目录] [CPU或DirectML]` | 校验并安装 SLANet / LaTeX-OCR；生成 4×3 表格并验证结构和单元格文字，验证 `x²+y²=1` 的 LaTeX 及取消；需先配置推荐 OCR。源目录含 `table.onnx,encoder.onnx,decoder.onnx,image_resizer.onnx,tokenizer.json`，可含上游 `formula-sample.png`；省略时联网下载，不修改用户设置 | `specialist-model-test.txt`、`specialist-table-result.txt` |
| `--cutout-model-self-test [本地模型绝对路径]` | 固定测试 U²-Net 轻量模型，不给路径时下载；本地文件仍检查对应固定 SHA256；验证安装、输入输出和本地测试图的透明蒙版推理，不代表六个模型均已实测 | `cutout-model-test.txt` |
| `--local-translation-self-test [下载目录] [CPU或Vulkan]` | 下载固定运行库及当前默认 Qwen3.5 4B 模型（约 2.81 GiB，运行库另计）、校验 SHA256，实际英译中并收尾子进程；默认 CPU，指定 GPU 时需先提供目录参数 | `local-translation-test.txt` |
| `--recording-setup-self-test` | 联网下载官方 VC++ x64 安装包，验证 Windows 信任签名及微软发布者；不执行安装器、不触发 UAC、不安装系统组件 | `recording-setup-test.txt` |
| `--recording-device-self-test` | 在后台线程连续枚举设备 10 次，验证 ID、名称和去重；允许没有麦克风／摄像头，只读取设备列表，不启动捕获 | `recording-device-test.txt` |
| `--recording-capture-self-test` | 显示生成的测试窗口，仅录制该小区域；检查 WGC / DXGI 软件编码与 WGC 优先硬编的 MP4 尺寸、帧数和时长，解码验证区域边框未录入，并实测工具条配置按钮打开／收起／重开及关闭清理；不启用音频／摄像头 | `recording-capture-test.txt` |

例如，检查 DirectML 的第 0 块显卡：

```powershell
# 使用旧目录或自选目录时，请将此变量改为当前实际数据目录。
$dataDirectory = (Resolve-Path -LiteralPath '.\bin\Release').Path
$modelTest = Start-Process -FilePath '.\bin\Release\NimCap.Screenshot.exe' -ArgumentList '--ocr-model-self-test DirectML 0' -WindowStyle Hidden -Wait -PassThru
Write-Output "MODEL_SELF_TEST_EXIT=$($modelTest.ExitCode)"
Get-Content -LiteralPath (Join-Path -Path $dataDirectory -ChildPath 'Diagnostics\ocr-model-test.txt') -Encoding utf8
```

真实模型和下载源的固定版本、来源与许可见[配置与依赖](配置与依赖.md)。判断结果应同时核对退出码和本次诊断内容；小样本通过不代表复杂文字、真实人物发丝、半透明边缘或所有 GPU 的效果验收。

2026-11-15 识别专项：PaddleOCR 在 CPU / 本机 DirectML #0 上通过多行中英文及 100%／150%／200% 样本、原图坐标验证；SLANet 在 CPU / 本机 DirectML 上通过 4×3 表格结构及 OCR 单元格文字匹配；LaTeX-OCR 两种设备均通过圆方程与取消验证。扩展公式样本校验分式、根号、积分和求和结构，但不等于逐字符准确率验收：积分长式存在 `n=0 → n=n` 的误识别，见配置文档。通用自检覆盖表格合并占位、非法输出、词表解码和屏幕取词三档 DPI 避让；混合多屏实际悬停及不同厂商显卡需继续人工验证。

设备枚举和实际录屏检查无需联网。实际录屏专项会显示一个测试窗口并读取当前显示器的小区域，请单独运行，避免其他窗口遮住测试画面；生成的 MP4 留在程序目录下的独立 `recording-check-<GUID>` 目录，诊断中记录具体路径。这些专项检查不替代真实设备音频／摄像头和长时间录制验收。

### 竖向长截图样本与接缝回归（P1-6）

运行 `dotnet run --project tools/ScrollingChecks -c Release`。覆盖竖向正负位移、回滚不重复、固定栏、生成的文章／聊天／分页场景、Edge 渲染 PNG，以及手动采集遇到不确定匹配后的原帧保留、零位移待修正、预览自动展开接缝、应用位移、撤销／重做和工程往返。产品采集入口固定竖向；底层横向代码仅作遗留回归，不承诺、不验收。

自动或手动采集在首个不确定匹配处停止，保留原帧并转入接缝预览；零位移只表示未定位，不扩展输出。人工输入非零位移后记录 `ManuallyAdjusted`，不把原算法结果伪装成可靠。重匹配遇到不确定结果也恢复零位移待修正。原始帧对照、固定栏裁除和 `.ssscroll` 保存可继续使用。没有实际重叠时须重新采集，不能靠调整位移补出遗漏内容。

真实应用 PNG／工程样本的导出、人工标定位移、重放格式及浏览器／Electron／Office 竖向矩阵见 [样本说明](../tools/ScrollingChecks/Samples/README.md)。原有 `Edge` 样本来自实际浏览器渲染，但使用 CSS 平移视口；无界面真实滚动采集曾出现合成画面未稳定的情况，未作为通过证据。

### 录屏长测、回退与设备拔插专项（P1-5）

以下命令从仓库根目录运行，会显示 960×540 DIP 动态窗口并录制其物理像素区域。拔插模式会捕获显式选择的音频／摄像头设备，产物留在 `.artifacts/recording-checks/<GUID>`；请使用测试设备及测试声音，不要在测试区域显示私人内容。无参数仍运行原有合成编码与界面回归。

```powershell
dotnet run --project tools/RecordingChecks -c Release -- --devices
dotnet run --project tools/RecordingChecks -c Release -- --soak 30 WGC software
dotnet run --project tools/RecordingChecks -c Release -- --soak 60 WGC hardware
dotnet run --project tools/RecordingChecks -c Release -- --soak 30 DXGI software
dotnet run --project tools/RecordingChecks -c Release -- --soak 30 WGC software --microphone '设备 ID' --speaker '设备 ID' --camera '设备 ID'
dotnet run --project tools/RecordingChecks -c Release -- --fallback
dotnet run --project tools/RecordingChecks -c Release -- --hotplug microphone '枚举得到的设备 ID'
dotnet run --project tools/RecordingChecks -c Release -- --hotplug speaker '枚举得到的设备 ID'
dotnet run --project tools/RecordingChecks -c Release -- --hotplug camera '枚举得到的设备 ID'
```

`--soak` 自动执行预热 5 秒、连续 600 秒、再次录制 5 秒；可通过显式设备 ID 同时开启音频和摄像头，不传设备参数则均关闭。每 5 秒落盘 `resources.csv`，检查各 MP4 尺寸、有效时长（误差 ≤0.6 秒）并解码前／中／后三处缩略图。跳过前 60 秒后比较头尾各 6 个样本均值：私有内存增长 ≤64MiB、句柄增长 ≤100；每次完成并等待两秒后，相对本次启动基线以及预热结束基线的私有内存增长 ≤128MiB、句柄增长 ≤100。这是有界资源增长检查，不代表证明所有原生资源均无泄漏。完整证据写入 `report.json`；失败保留 CSV 和 `failure.txt`，原生崩溃也应检查进程退出码及事件查看器。

`--fallback` 以每会话内部钩子在硬编首帧前注入初始化异常，验证实际顺序恰为硬编→软件一次，再用原生软件编码生成并解码 MP4。它验证服务重试路径，不模拟 GPU 驱动崩溃，也不证明硬编已实际使用（原生库还可能自行回退）。没有全局环境变量或生产 UI 故障开关。

`--hotplug` 等待人工／外部 USB 测试夹具在录制至少 10 秒后拔出指定设备（最长等待 600 秒），自动验证检测到缺失、停止保存、MP4 可解码；等待最多 120 秒重连同一 ID，再自动录制 10 秒。当前产品策略为断开后结束会话，不自动续接原 MP4。没有设备拔插证据、原生报错导致文件未保存或重连后无法录制均失败；不自动禁用系统设备。

退出码：0 表示所选专项的功能、资源与实际帧率均通过；1 表示参数／采集／解码／设备验收失败；2 表示功能完成但资源阈值或实际平均帧率未通过。平均帧率按原生帧回调数／有效录制时长计算，必须在目标 ±5% 内；文件标称帧率不代替实际吞吐量。UI 同样在有效录制两秒后按 ±5% 提示。`events.jsonl` 实时保存会话状态、回退原因及检测到的设备变更时刻；所有报告默认留在被 Git 忽略的产物目录。

### 抠图新增覆盖与已知崩溃

通用自检已覆盖六个模型的目录定义、General / HR 配置契约、默认模型保留、配置序列化以及合成 ONNX 的 alpha 输出。HR 配套导出已经包含 sigmoid，测试检查不会再执行 sigmoid 或 min-max。设置布局自检检查选择 General 完整版／HR 时尺寸和契约正确回填，且不会改变默认选择。

这些测试不加载 GB 级真实权重，不能证明 HR 在 GPU 上可用。2026-11-15 的本机 Windows Application Error / .NET Runtime 记录确认：高质量验证版连续两次在 `nvd3dumx.dll`（`32.0.16.1742`）以 `0xc0000005` 终止进程，且出错偏移一致。此前还出现 DirectML `8007000E`，任务管理器显示专用显存接近满载；这支持优先调查 GPU 执行和内存压力，但未单独证明具体算子、资源释放逻辑或驱动是最终根因。

排查时同时记录模型 ID、运行设备、驱动、超时、切换过的模型、崩溃前专用显存及系统内存。诊断文件不一定捕获原生崩溃，应另查 Windows“事件查看器 → Windows 日志 → 应用程序”，以及存在时的 `%LocalAppData%\CrashDumps\NimCap.Screenshot*.dmp`；系统或外部工具生成的转储可能含截图／文字等敏感内容，不应直接公开。

当前已实现 ONNX 子进程隔离、失败会话释放、显存预算检查及 GPU 故障后 CPU 重试，取消与超时会结束本次 worker。进程隔离与恢复专项使用小型模型验证故障边界，不等于上述真实 HR 模型或驱动问题已解决；原生故障根因和多品牌 GPU 质量、性能仍需专项验收。实现与诊断字段见[异常与推理隔离](异常与推理隔离.md)。
