# 配置与依赖

[文档中心](README.md) · [使用指南](使用指南.md) · [构建与测试](构建与测试.md)

本文集中说明模型、运行环境和 API 的配置；日常操作见[使用指南](使用指南.md)，开发组件清单见[架构与依赖参考](ARCHITECTURE.md#dependencies)。所有下载均由用户主动触发，失败或取消保留原配置；下载配置完成后保存设置。

## 模型大小与识别效果

识别准确率受所选 AI 模型的大小与能力影响。同系列、同任务且训练与量化条件相近时，较大参数模型通常能更好地处理复杂内容；轻量模型则更节省内存、显存与处理时间。实际效果还受模型结构、训练数据、语言覆盖、量化方式和图片清晰度影响，下载文件更大并不必然意味着识别更准确。

OCR、表格结构、公式识别和本地翻译分别使用各自的模型。应在满足对应输入输出契约的兼容模型中，按任务、设备资源和实际样本选择；更换 Qwen 翻译模型不会改变 OCR、表格或公式识别结果。证件字段提取和敏感文字检测复用 OCR，Qwen 可辅助敏感文字中的人名与地址分析。

## 配置速查

去水印模型在识别窗口的“去水印”页面下载／导入，独立选择 CPU 或 DirectML。
MI-GAN、LaMa、Moebius 使用不同输入输出契约；区域／智能识别另需 SLBR。四种模型均提供官方源与中国源，可在当前页面自动下载、校验及配置，无需用户转换模型。
固定文件、大小、校验值与导出说明见[去水印与图像修复](去水印与图像修复.md)。

| 能力 | 本地 / API 与设备 | 首次配置 |
|---|---|---|
| [PaddleOCR](#ocr) | 本地 ONNX，CPU 默认，可选 DirectML GPU | 一键下载检测、识别模型及配套字典 |
| [Tesseract / Windows OCR](#ocr) | 本地，不受 ONNX 设备设置影响 | Tesseract 一键下载字库；Windows OCR 一键选择已有语言，缺少时打开系统安装入口 |
| [表格与公式](#plugins) | 本地 ONNX，CPU / DirectML GPU；可选外部插件 | 表格一键配置 SLANet 及缺失 OCR；公式一键配置编码器、解码器、尺寸模型和词表 |
| [一键抠图](#cutout) | 本地 ONNX，使用 OCR 页的 CPU / DirectML GPU 设置 | U²-Net / BiRefNet 按需下载，独立配置与默认选择 |
| [本地翻译](#translation) | 本地 Qwen / llama.cpp，CPU 或 Vulkan GPU | 一键下载 GGUF 模型与匹配运行库；不是 ONNX 模型 |
| [API 翻译](#translation) | MyMemory / Google 网页适配 / LibreTranslate | 选择服务、配置并授权，费用与额度从设置中的官网入口查询 |
| [录屏](#recording) | 本地 WGC / DXGI 与系统编码器 | 一键检查并安装缺失运行组件；设备权限由用户在系统设置中开启 |

模型和字库位于 `<数据目录>\models`。数据目录优先按 exe 旁的 `data-location.json` 选择；没有该文件时，只有 exe 目录没有应用数据项、且 `%LocalAppData%\SnapSharp` 存在应用数据项，才使用旧目录，否则使用 exe 所在目录。可在“设置 → 常规 → 本地数据”修改，确认后下次启动迁移，完整规则见[使用指南](使用指南.md#data-directory)。诊断信息和自检结果位于 `<数据目录>\Diagnostics`。运行库下载使用独立目录；来源、固定版本与校验规则见各节。ONNX Runtime 与 DirectML 随程序提供，无需另外安装 ONNX、Python 或 CUDA。模型格式相同不代表可以互换，必须满足对应输入、预处理和输出契约。

## 官方源与中国源

在设置的“OCR 与识别”“一键抠图”或“翻译”页，可通过“模型下载源”统一切换下载地址。默认使用官方源；访问官方源较慢时可选“中国源”（英文界面为“China source”），下次点击下载立即生效，点击“保存设置”可记住选择。下载过程中不能切换，需先取消当前下载。

| 文件来源 | 官方源 | 中国源 |
|---|---|---|
| OCR 模型包 | PyPI | 清华 PyPI 镜像 `pypi.tuna.tsinghua.edu.cn` |
| Hugging Face 模型 | `huggingface.co` | `hf-mirror.com` |
| GitHub 模型、字库与 llama.cpp 运行库 | GitHub | 第三方加速 `gh-proxy.com` |
| 表格模型 | ModelScope | ModelScope（已在国内） |

镜像使用相同的固定版本和文件校验值，下载后仍验证大小／校验和；镜像故障时可切回官方源重试。本地翻译已下载的 `.part` 文件在切换源后可继续断点续传。镜像服务由第三方维护，可用性和速度取决于当前网络；HF-Mirror 部分大文件会重定向到 Hugging Face CDN。

### 已下载模型复用

再次点击下载前，会在当前数据目录的 `models` 中检查对应模型，包括旧版生成的随机名称目录。模型文件、字典或词表的大小和固定校验和全部匹配时，直接复用原文件，不联网、不新建模型目录；切换官方源／中国源也沿用同一份模型。缺失、损坏或版本不符的模型不会被复用。下载和安装会串行检查，避免多次点击或并发请求创建重复副本。

Tesseract 中英双语字库可直接用于单一语言；为英文目录补充中文时，只下载缺少的字库并在原目录安装。已有多个旧副本时，会优先复用最近的有效目录，不会自动删除其他目录或用户文件。本地翻译继续使用已有的校验、复用和断点续传机制。

## 模型路径与文件夹移动

模型配置支持相对于 `NimCap.Screenshot.exe` 所在目录的路径，如 `models\ocr\detection.onnx`。exe 所在文件夹及其子目录内的模型自动保存为相对路径，外部目录的模型保留绝对路径。此规则适用于 OCR 模型与字典、Tesseract 字库目录、所有抠图模型、表格模型、公式模型目录，以及本地翻译模型和 llama.cpp 运行库。

相对路径始终以 exe 所在目录为基准，和启动程序时的工作目录无关。旧版绝对路径配置仍可读取，保存一次设置后会自动转换。退出程序后，将 exe、`settings.json`、`models` 等一并移动到新位置即可继续使用；仅移动 exe 不会搬运外部数据目录或外部模型。通过设置迁移数据目录时，程序会同步更新相对／绝对路径。

## 1. OCR 与识别

默认策略：已经适配的图像模型优先本地 ONNX，OCR 为 PaddleOCR、抠图新配置默认为 BiRefNet General Lite，U²-Net 保留为快速模式；CPU 默认启用，GPU 由用户选择。首次通过一键下载自动填写模型配置，保存后使用；不覆盖已有引擎选择。Windows OCR、Tesseract、自备兼容模型、在线 API 都是可选项。目前本地翻译是 Qwen / llama.cpp 的 GGUF 路线，并非 ONNX；不能只更换模型后缀。超分、人脸检测打码、文档矫正、Whisper 等仍需各自模型、预处理及解码实现，不因已有 ONNX Runtime 而视为已完成。

首次使用请打开设置左侧的“OCR 与识别”。默认使用 PaddleOCR，中英文混合识别：选择“PP-OCRv4 · 中文＋英文”，点击“一键配置推荐 ONNX OCR（下载模型）”，完成后点击“保存设置”。也可继续浏览选择自己的模型和字典。未配置模型不会在识别时自动下载或静默切换后端。仅需系统 OCR 时可手动选 Windows，默认语言为 `zh-Hans`，需安装对应系统语言包；此选项不是 PaddleOCR 的语言开关。

### 一键下载模型与字典

- 当前内置一个配套模型包：RapidOCR `1.3.24` 分发的 PP-OCRv4 检测／识别 ONNX，支持中文与英文；其他兼容模型仍可手动选择本地文件。
- 仅点击下载时联网，从 PyPI 的 `files.pythonhosted.org` 或所选清华镜像获取固定版本，约 14.2 MB；支持进度和取消，不上传截图或文字。
- 下载包的 SHA256 固定为 `4282ff0b8db05ad2a53afc8d0ef2e7d879c53022fc61a4f8e84c58d737822cd2`。校验后只提取两个 ONNX 文件，从识别模型元数据生成匹配的 UTF-8 字典；不安装或执行 Python 代码。
- 文件保存在 `<数据目录>\models\ppocr-v4-zh-en-<唯一标识>`，附来源记录 `source.txt`。成功后回填三个路径，保存设置后生效；失败／取消保留原配置，不覆盖原模型。
- 上游：<https://github.com/RapidAI/RapidOCR/tree/v1.3.24>，Apache-2.0；下载分发包：<https://pypi.org/project/rapidocr-onnxruntime/1.3.24/>。如使用其他模型，应另行核对对应权重许可。

### 可选 Tesseract 离线 OCR

已内置免费开源 NuGet `Tesseract` 5.2.0（Apache-2.0），包括原生引擎，不需要用户安装 NuGet、Python 或命令行工具。设置 → OCR 与识别 → Tesseract 区域，选择字库后点击“一键下载并配置 Tesseract”，成功后会自动选择引擎并填好字库路径、识别语言，最后保存设置。下载可取消，失败保留原配置。也可选择现有的 `.traineddata` 目录并填写语言组合。

| 内置字库 | 识别语言 | 下载大小 |
|---|---|---|
| 简体中文＋英文 | `chi_sim+eng` | 约 6.3 MB |
| 英文 | `eng` | 约 3.9 MB |
| 简体中文 | `chi_sim` | 约 2.4 MB |

字库来自官方 [tessdata_fast](https://github.com/tesseract-ocr/tessdata_fast/tree/87416418657359cb625c412a48b6e1d6d41c29bd)，固定提交 `87416418657359cb625c412a48b6e1d6d41c29bd`，Apache-2.0。英文 SHA256 为 `7d4322bd2a7749724879683fc3912cb542f19906c83bcc1a52132556427170b2`；简中为 `a5fcb6f0db1e1d6d8522f39db4e848f05984669172e584e8d76b6b3141e1f730`。每个文件检查大小与 SHA256，安装后验证引擎可加载；保存在 `<数据目录>\models\tesseract-fast-<唯一标识>`，附 `source.txt`，不会覆盖现有模型。

Tesseract 在后台串行运行，使用 LSTM 与自动页面分割，输入最长边由 OCR 设置限制，识别行坐标还原到原图像素。原生识别阶段不能即时中断，停止／超时会在原生调用返回后生效，期间不会放行第二个 Tesseract 任务。CPU 线程设置仅用于 ONNX。真实测试已识别“Hello 世界 123”，不代表复杂版面或所有截图的精度；可按样本在三种引擎间手动选择。

“检查当前 OCR 引擎与模型”随所选引擎检查：Tesseract 加载所选字库、Windows 检查语言包、PaddleOCR 加载模型和字典。Windows 可一键选已有语言，缺少语言包时打开系统安装入口。切换引擎会保留其他引擎的配置。

### PaddleOCR CPU / GPU 与模型契约

“OCR 与识别”明确标出三种本地引擎，当前没有云 OCR API。PaddleOCR 的 ONNX 计算设备可选 CPU 或 DirectML GPU，并填写显卡编号（默认 0）；抠图在“一键抠图”页独立选择设备，旧配置未设置时沿用通用设备。微软 DirectML 运行库随应用提供，不需 CUDA，支持具备相应 DirectX 12 能力的 NVIDIA / AMD / Intel 显卡和驱动。GPU 初始化或推理失败时可在独立 worker 内回退 CPU；出错适配器在本次启动期间后续使用 CPU，并记录诊断，不改变保存的设备选择。不支持的算子也可能使用 CPU。Windows OCR 与 Tesseract 不受 ONNX 设备设置影响。设置页提供 PaddleOCR、DirectML 官方链接。

需要三个匹配的本地文件：文本检测 `.onnx`、文本识别 `.onnx` 和 UTF-8 字典 `.txt`（每行一个标签）。选择可信来源的 DB 检测与 CTC 识别导出模型，例如 PaddleOCR PP-OCR 系列的兼容导出版本；并非该系列所有导出都具有相同接口。

| 项目 | 当前适配器要求 |
|---|---|
| 输入 | 单 float32 RGB NCHW `[1,3,H,W]`；固定尺寸以模型为准，动态尺寸由设置／图片决定；每轴 16–2048 |
| 检测预处理 | RGB ImageNet mean/std，最长边限制，动态尺寸向上取 32 倍数 |
| 检测输出 | 第一个输出为 `[1,1,H,W]` DB 概率图，连通区域阈值化及轴对齐外接框扩展 |
| 识别预处理 | RGB `[-1,1]`，动态高 48，保持比例并在右侧补 0 |
| 识别输出 | 第一个输出为 `[1,T,C]` CTC 概率或 logits；索引 0 为空白，字典可额外追加空格以匹配类别数 |
| 当前限制 | 最多 256 个文本区域；无旋转校正、透视矫正；不支持原生 `.pdmodel`、多输入／量化模型或自回归解码 |

“检查模型文件”只验证可以加载和字典存在；完整输出、类别数和字典对应关系在运行时检查。错误模型应切换为匹配的导出文件，而不是仅修改扩展名。倾斜、竖排、复杂版面准确率需要单独验收。文字按行整理，不承诺自动恢复段落语义。

模型来源参考：<https://github.com/PaddlePaddle/PaddleOCR>（项目 Apache-2.0）。权重文件的版本、来源、许可证、大小和 SHA256 应由部署者单独记录，项目许可证不自动替代第三方权重的许可。

## 2. 一键抠图

复制图片内容后，点击托盘菜单“识别粘贴板图片…”。窗口先显示剪贴板图片，不自动运行：可选择文字 OCR 后开始，或切换“一键抠图”选择模型后运行。翻译需先 OCR 识别文字，再点击“翻译…”。剪贴板导入使用支持 PNG / DIB / DIBV5 的读图组件并保存独立像素快照；没有图片会明确提示，不把图片链接或文本路径当作图片。

在设置 → 一键抠图中选择默认模型，再选择要配置的模型，点击“一键下载并配置抠图”，完成后保存设置。下载自动填写所选模型的独立路径、预处理与输入边长，不会覆盖其他模型配置。抠图窗口可临时选择模型，点击“一键抠图／重新运行”，不会修改保存的默认选择；未安装的模型会提示前往配置，不会悄悄替换。

| 模型 | 用途 | 大小 / 输入 | 来源与固定校验 |
|---|---|---|---|
| u2netp | 快速预览 / CPU 模式 | 4.4 MB / 320 | rembg；SHA256 `309c8469258dda742793dce0ebea8e6dd393174f89934733ecc8b14c76f4ddd8` |
| birefnet-general-lite | 新配置的默认精修 | 224 MB / 1024 | rembg；上游 MD5 `4fab47adc4ff364be1713e97b7e66334` |
| birefnet-portrait | 人像精修 | 973 MB / 1024 | rembg；上游 MD5 `c3a64a6abf20250d090cd055f12a3b67` |
| birefnet-matting | 发丝 / 玻璃软透明度精修（效果需实测） | 941 MB / 1024 | Hugging Face `emrikol/birefnet-matting-onnx` 社区导出；版本 `0d58d809b3a360b44c556223d2f5812aeace9ba3`；SHA256 `f0843e38f6a4e88efc8c5fad4178ad7ed6c818346ce12f82e7b579324fe7e0c5` |
| birefnet-general | 高质量通用精修，完整版作为 Lite 的按需备选 | 973 MB / 1024 | rembg；上游 MD5 `7a35a0141cbbc80de11d9c9a28f52697` |
| birefnet-hr-matting | 2048 高质量发丝 / 半透明精修（效果需实测） | 932 MB / 2048 | Hugging Face `PinkPixel/birefnet-hr-matting-onnx` 社区 FP32 导出；版本 `792518b9d4dfe9793891712677de25e554f948c6`；SHA256 `a548a1f3307250766bef50b174026b3cfa39a695bc1e42ec131c14fe82797ffd` |

新增高质量选项同样在设置中一键下载并配置，可设为默认，也可仅在抠图窗口临时选择；不改变原有默认模型。HR Matting 输入为 ImageNet 归一化 float32 RGB `[1,3,2048,2048]`，输出已经是 `[1,1,2048,2048]` 的 alpha 概率，使用 `BiRefNetAlpha` 契约，仅限幅，不重复 sigmoid、不做 min-max。选择 FP32 版本，不把 FP16 / INT8 导出视为自动兼容。

HR 模型更耗内存／显存，CPU 可能较慢；可在“OCR 与识别”页选择 DirectML 或把推理超时提高至 120 秒。模型卡声称支持的设备不等于本项目已实测兼容；真实质量、内存占用及 GPU 算子兼容性仍需在目标设备验收，不保证每张图片都优于 Lite。

### 设备、超时与 DirectML 故障

“设置 → 一键抠图”提供独立 CPU／DirectML 选择；适配器编号沿用 OCR 页。CPU 仅列出 U²-Net 与 General Lite 预设，其余内置预设在 DirectML 下提供。旧配置没有独立设备时沿用通用 ONNX 设备。

超时共用“设置 → OCR 与识别 → 语言与资源限制 → 推理超时（1–120 秒，可取消）”，默认 30 秒。等待、首次加载、预处理和推理可能计入；增加超时不能解决内存不足。

HR + DirectML 曾观察到内存分配失败及原生驱动访问冲突。当前 PaddleOCR、表格、公式与抠图已通过独立 ONNX worker 执行；每次操作最多缓存四个会话，结束即释放。GPU 初始化／推理失败、显存预算不足或 GPU worker 异常退出时，可在剩余超时内回退 CPU；出错适配器在本次启动期间后续使用 CPU，保存的设备偏好不变。取消与超时终止 worker。预算检查不是精确资源预测，CPU 重试仍可能因内存或时间不足失败。

出现 `8007000E`／`E_OUTOFMEMORY` 时降低模型负担，先用 General Lite／U²-Net。子进程隔离不等于真实 HR 模型、多品牌显卡和驱动均已验收。实现与诊断见[异常与推理隔离](异常与推理隔离.md)。

按需安装 3–4 个即可，Portrait / Matting 可二选一。支持进度和取消，失败不更改原配置，临时文件清理，每次使用独立目录避免覆盖；大文件流式下载到磁盘，不整体缓存在内存。校验通过后还会打开 ONNX 检查输入输出契约。ONNX Runtime 已随程序提供，无需安装 Python。旧版单模型配置会迁移并保留原默认模型。模型选择和运行发生在抠图窗口，尚非拖动框选期间的持续实时预览。

也可选择自己的本地 `.onnx` 文件及与导出代码一致的预处理方案。模型必须单 float32 RGB `[1,3,H,W]` 输入；第一个输出需为 `[1,1,H,W]`、`[1,H,W]` 或 `[H,W]` 的前景蒙版。

| 方案 | 输入归一化 | 输出处理 |
|---|---|---|
| U2Net | ImageNet mean/std | 蒙版 min-max 归一化 |
| ISNet | RGB 减 0.5，std=1 | 视为 0–1 概率 |
| BiRefNet | ImageNet mean/std | logits → sigmoid → min-max（配套 general-lite / portrait） |
| BiRefNetMatting | ImageNet mean/std | logits → sigmoid，保留软 alpha，不做 min-max |
| BiRefNetAlpha | ImageNet mean/std | 已输出 alpha，只限幅到 0–1，不重复 sigmoid / min-max（配套 HR Matting） |

这些名称表示适配契约，不代表支持所有同名模型。例如已经输出概率的 BiRefNet 导出文件不能再按 logits 使用。动态输入尺寸使用设置值；固定尺寸以模型声明为准。首输出顺序、掩码方向或归一化不同的模型需先适配。

小型模型下载源：<https://github.com/danielgatis/rembg/releases/download/v0.0.0/u2netp.onnx>，上游 U-2-Net 使用 Apache-2.0；BiRefNet 使用 MIT。来源参考：<https://github.com/xuebinqin/U-2-Net>、<https://github.com/ZhengPeng7/BiRefNet>、<https://huggingface.co/emrikol/birefnet-matting-onnx>、<https://huggingface.co/PinkPixel/birefnet-hr-matting-onnx>。模型权重不内置分发，RMBG-2.0 非商用权重不在下载目录中；MODNet、General HR 等扩展未接入。

蒙版恢复至原始分辨率，并与原有 alpha 相乘。复制、贴图和 PNG 保留透明度；保存窗口默认 PNG，手动改为 JPEG/BMP/PDF 将失去透明背景。原始图片不会被覆盖，覆盖已有文件需另行确认。

## 3. 翻译引擎

### 本地翻译与 API 选择

设置 → 翻译、API 与隐私页顶部是 Qwen（通义千问）本地模型区，默认选择 Qwen3.5 4B Q4_K_M（约 2.81 GiB）；也可选 2B、9B、27B Q4_K_M。检测到至少 24 GiB 专用显存时额外显示 27B Q5_K_M。选择 CPU 或 Vulkan GPU 后，点击“下载并配置本地翻译”下载所选模型；无需 Python、Docker、API 密钥。在线 API 和图片搜索分别位于下方独立区域。GPU 需要兼容 Vulkan 的驱动；若未检测到模型层成功卸载至 GPU，则报错，不自动回退 CPU。VC++ x64 缺失时可使用页面上的运行库配置入口。

所有模型都来自固定的 GGUF 仓库修订，并按文件大小和 SHA256 校验；运行库固定为 llama.cpp b12470 CPU / Vulkan Windows x64 包，也按大小与 SHA256 校验。模型体积约为：2B 1.30 GiB、4B 2.81 GiB、9B 5.75 GiB、27B Q4_K_M 16.75 GiB、27B Q5_K_M 19.53 GiB。下载可取消，原配置不变，成功后自动填写路径。译文通过带随机鉴权的本机回环端口取得，子进程在完成、取消或超时后退出；不向外部 API 发送文字。单次 6000 字符、3 分钟超时，支持英文／中文等语言代码。模型可能误译，请人工核对。

| 选择 | 运行位置 / 费用 | 官方查询 |
|---|---|---|
| 本地 Qwen3.5 + llama.cpp | 本机 CPU / Vulkan GPU，无 API 费用；模型 Apache-2.0，运行库 MIT | [模型目录](https://huggingface.co/bartowski)、[运行库](https://github.com/ggml-org/llama.cpp) |
| API MyMemory | 第三方服务，有公共免费额度及限流，单次 500 UTF-8 字节 | [官方额度](https://mymemory.translated.net/doc/usagelimits.php) |
| API Google 网页适配 | GTranslate 开源包免费；非官方 Cloud API，不保证接口免费或稳定 | [Google 官方 Cloud API 定价](https://cloud.google.com/translate/pricing)，此价格不代表网页适配额度 |
| API LibreTranslate | 自定义运营商决定价格；开源软件免费不等于托管 API 免费 | [官方托管方案](https://portal.libretranslate.com/)，自定义实例需向运营商查询 |

只有 API 翻译需要“允许在线翻译”及逐次发送确认。本地翻译可在在线授权关闭时直接使用；失败不换服务商、不覆盖原文。现有用户保存的 API 选项保持不变。设置页有“查看所选服务官网 / 价格 / 免费额度”按钮。

### API 配置与发送确认

“翻译、API 与隐私”中的在线翻译和识图默认关闭。开启 API 功能并设置端点后，每次仍需确认发送内容和完整地址。只允许 HTTPS 或本机回环 HTTP，禁止地址内嵌账号，不自动跟随重定向。本地翻译不需要在线授权。

- 翻译：先在设置中选择 MyMemory 或 Google，再点击“一键配置所选引擎 · 英译中”并保存。MyMemory 无需地址／密钥或本地模型，有免费额度，单次最多 500 UTF-8 字节，不支持 `auto`。Google 使用免费开源 NuGet `GTranslate` 2.4.0（MIT），无需模型或密钥，单次最多 5000 字符，支持 `auto`；它仍是第三方联网接口，可能限流、不可达或变更，不保证永久免费／稳定可用，不自动回退到其他服务商。
- API 使用：OCR 后在文字页点击“翻译…”，可只翻译选中段落，发送前确认，译文出现在“翻译结果”页。可粘贴文本；设置内可逐次确认发送 `Hello` 测试连接。选择引擎或一键配置本身不发送文字；所有实际 API 翻译仍需要启用授权和逐次确认。
- 自定义翻译：选择 LibreTranslate 后自行配置服务地址，POST JSON `{q,source:"en",target:"zh",format:"text"}`，响应 `{translatedText:"…"}`。支持源语言 `auto`（依服务能力），当前不支持 API Key 配置。原有自定义地址不会被一键预设覆盖。
- 以图搜图：POST multipart，字段 `image` 为 PNG；响应 `{url:"https://…"}`。确认后才上传，成功后用浏览器打开返回地址。需要自建或兼容的服务，不是任意搜索引擎网址。

上限：自定义翻译 50000 字符、MyMemory 500 UTF-8 字节、Google 5000 字符、图片上传 8 MB、响应 1 MB，25 秒网络超时。GTranslate 仅允许向确认的 Google 地址发送翻译请求，拒绝服务重定向，取消会传递到实际网络调用。源图片与原文不会因服务失败而丢失。自动回归测试通过真实 GTranslate 包与本地假 HTTP 处理器验证，不向真实翻译服务发送内容；公共服务需用户通过连接测试确认可用性。

## 4. 本地表格、公式及插件

设置 → OCR 与识别 → 本地表格与公式，点击对应“一键配置”，完成后保存。两者均使用本机 ONNX CPU / DirectML GPU，不上传图片、不需要 API、Python 或插件。保留已有外部插件选择；点击对应一键配置会主动清空该项插件 ID 并选择内置识别器。失败或取消保留原配置，下载文件使用独立目录，不覆盖原模型。

### 表格：PP-Structure / SLANet

内置中文 SLANet 结构模型，来自 [RapidTable v2.0.0](https://www.modelscope.cn/models/RapidAI/RapidTable/files?Revision=v2.0.0)，Apache-2.0，7,790,807 字节，SHA256 `ddfc6c97ee4db2a5e9de4de8b6a14508a39d42d228503219fdfebfac364885e3`。一键配置同时补齐所选 PaddleOCR 缺少的配套文件；选择 Windows / Tesseract 时保留所选 OCR，字库在相应区域配置。

预处理为 BGR、ImageNet 归一化、最长边缩放至 488 后右侧／底部补零。模型含 `character` 元数据，输出 `[1,T,V]` 结构概率及 `[1,T,4或8]` 单元格坐标。解码行列、跨行和跨列，按空间重叠匹配当前 OCR 文字，坐标还原到原图；禁止合并重叠和超过 100000 格。请框选单张表格，复杂无边框、多表混排仍需核对。可编辑行列与合并范围并导出 CSV/XLSX；CSV 转义公式前缀，XLSX 使用文本单元格。

### 公式：LaTeX-OCR

从 [RapidLaTeXOCR v0.0.0](https://github.com/RapidAI/RapidLaTeXOCR/releases/tag/v0.0.0) 下载固定资产 ID 的 `encoder.onnx`、`decoder.onnx`、`image_resizer.onnx` 和 `tokenizer.json`，共约 171 MiB。权重来自 [LaTeX-OCR](https://github.com/lukas-blecher/LaTeX-OCR)，MIT；下载来源与每个文件的固定大小／SHA256 写入模型目录 `source.txt`，应用代码中的清单用于校验。包元数据与项目许可可能不同，部署时以对应文件上游许可为准。

使用灰度、前景裁剪、自动反色、32 倍数填充与尺寸预测，再执行编码器及自回归解码器；词元 1 开始、2 结束，最多生成 512 个词元。编码器／尺寸模型输入为 `[1,1,H,W]` float32；解码器使用 int64 词元、bool mask 和 float32 context。仅支持配套词表及模型，不接受任意同名文件。选择单个清晰公式，输出可编辑、复制并导出 `.tex`；长式、手写或模糊图片需人工核对。CPU / GPU 及推理超时沿用 OCR 设置，较长公式可适当提高超时。

真实样本覆盖圆方程、双曲线、求根公式及积分／求和。前三类输出可用；积分长式样本曾将求和下标 `n=0` 识别成 `n=n`，并遗漏末尾句点，不能作为数学正确性保证。请核对下标、符号与括号后使用。

### 可选外部插件

仍可通过 `INimCapPlugin` / `IRecognitionPlugin` 接口加载并填写 ID。插件接收原图与 `task=Table` 或 `task=Formula`；表格 Metadata 为 `row,column,rowSpan,columnSpan`，定位为 `x,y,width,height` 原图像素坐标；公式须返回 `Kind=latex`。插件是本机可信代码，不是沙箱，遵守来源与签名策略。普通内置识别器 ID 为 `nimcap.screenshot.ocr`、`nimcap.screenshot.barcode`。

## 5. 屏幕取词与资源限制

托盘“屏幕取词（本次会话）”默认关闭，不保存为下次自动开启。鼠标停留后局部截图一次；同一停留位置不持续推理，鼠标移动后取消并隐藏结果。上限 480×140 物理像素，同一图片和配置命中缓存，不联网，最多一个任务。超时沿用识别设置，并限制在 15～120 秒；这与普通识别可设置的 1～120 秒范围不同。优先使用已配置或缓存的本地 OCR，缺模型时尝试已安装的 Windows OCR 语言包，不隐式下载。截图选区、长截图采集、设置及本应用活动窗口期间暂停；无可用引擎、截图失败或当前任务超时将关闭开关并提示。

结果窗口沿用应用主题且不抢焦点，依据目标显示器 DPI 将尺寸换算为物理像素，始终放在识别区外并保持在工作区内；没有空间时不显示。旧位置任务返回错误或取消不会关闭新一代会话；新位置稳定后会等待旧任务收尾再识别，避免永久漏识别与并行推理。

通用识别与抠图输入最多 1600 万像素；CPU 线程 1–8，默认 2；推理超时可配置 1–120 秒，默认 30 秒。ONNX 推理串行运行，每次 worker 操作最多缓存 4 个会话，操作结束即释放。限制不等于内存沙箱，请只加载可信模型。

## 6. 录屏运行环境

首次使用：设置 → 录屏（或录屏控制台顶部）→ “检查并一键配置录屏环境…” → “一键检查并安装缺失组件”。已安装组件不会重复下载；组件齐全后用生成图检查编码器，不采集桌面或设备。

使用 ScreenRecorderLib **7.0.1**（MIT），当前主程序固定为 **x64**，需要 Microsoft Visual C++ Redistributable x64 和 Windows Media Foundation。Windows N/KN 需安装 Media Feature Pack；Windows Server 需安装媒体组件。使用 Windows Graphics Capture，目标基线 Windows 10 2004 及以上。摄像头／麦克风还需要 Windows 隐私设置允许桌面程序访问。

“一键配置”具体行为：

- Visual C++ x64 缺失时，从微软 <https://aka.ms/vs/17/release/vc_redist.x64.exe> 下载，仅允许固定的微软 HTTPS 下载主机重定向，限制安装包 100 MB。下载到应用数据的独立目录，使用 Windows Authenticode 信任校验，并核对发布者为 Microsoft Corporation；校验失败绝不运行。微软地址提供可更新版本，因此使用签名和发布者验证，而非固定单个旧版本 SHA256。
- 通过官方安装器 `/install /passive /norestart` 安装，并由 Windows 请求管理员授权。Windows N/KN 缺少 Media Foundation 时，通过系统 DISM 安装 `Media.MediaFeaturePack~~~~0.0.1.0`，由 Windows 自行下载匹配系统版本的组件。
- 下载可取消；系统安装启动后等待完成，不强杀安装器。需要重启时明确提示，不自动重启电脑。取消 UAC 可重新尝试；安装退出码和失败原因会显示在窗口。
- 非 N/KN 的裁剪系统／Windows Server 缺失媒体组件时，显示具体缺失项并提供系统“可选功能”入口，需管理员修复适合该系统的组件；不把不匹配的功能包强装到所有 Windows 版本。
- 环境窗口提供麦克风、摄像头访问权限入口，系统权限仍需用户开启。只有当前录制勾选的设备会进入采集源。
- 组件检查通过后，实际用生成的 160×96 测试图验证系统 H.264 软件编码器、MP4 尺寸／时长／帧率。不会进行桌面、音频或摄像头测试。硬件编码器与设备兼容性仍需实际录制检查。

没有引入 FFmpeg、NAudio 或 Magick.NET；GIF 编码在本仓库内实现。Media Foundation 调用系统 H.264/AAC 编码器；ScreenRecorderLib 的 MIT 授权不等于 H.264/AAC 专利许可。发行方须按用途和市场单独核查相关义务。参见 [第三方声明](../THIRD-PARTY-NOTICES.md)。

## 7. 检查配置与故障定位

OCR 页的检查按钮按当前引擎加载模型或检查语言包；翻译页可测试所选本地引擎或在确认后发送 API 测试文字；录屏环境窗口用生成图验证软件 H.264 编码。检查成功不代表所有真实样本、GPU 或外设已完成验收。

真实模型下载、CPU / GPU 推理、录屏依赖签名和回归命令统一见[构建与测试](构建与测试.md#model-tests)。复杂文字精度、半透明抠图、长时间音画同步及设备兼容性仍按[路线图](<NimCap Screenshot 功能规格与路线图.md>)验收。
