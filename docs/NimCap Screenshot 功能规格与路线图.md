| ✅ 已完成 | 当前代码中已有完整用户入口，且具备基本异常处理 |

| 优先级 | 定义 |

## 二、屏幕捕获

| 编号 | 状态 | 功能 | 优先级 | 当前实现 / 推荐方案 | 验收标准 |
|---|---|---|---|---|---|
| C-01 | ✅ | 虚拟桌面全屏截图 | P0 | WGC 逐显示器取帧后由 SkiaSharp 按物理坐标合并；失败回退 GDI | 所有活动屏内容完整；屏幕间相对位置正确；无额外黑边 |
| C-02 | ✅ | 区域截图 | P0 | 每屏先捕获，再按物理像素矩形裁剪 | 结果尺寸与选区提示一致，边界误差不超过 1 物理像素 |
| C-03 | ✅ | 活动窗口截图 | P0 | 捕获触发时记录前台句柄，优先使用 DWM 扩展边框，失败回退 `GetWindowRect` | 正常窗口完整；NimCap Screenshot 自身获得焦点时能回退到其他顶层窗口 |
| C-04 | ✅ | 窗口悬停识别 | P1 | `WindowFromPoint` + `GetAncestor(GA_ROOT)`，过滤隐藏、工具、自身和 DWM cloaked 窗口 | 重叠窗口按可见 Z 序命中；高亮边界与实际窗口一致 |
| C-05 | ✅ | 多显示器枚举 | P0 | `EnumDisplayMonitors` 获取每屏物理矩形 | 每个活动显示器只出现一次；几何与 Windows 显示设置一致 |
| C-06 | ✅ | 负坐标显示器 | P0 | 全程保留虚拟桌面负坐标，拼接时减去虚拟桌面左上角 | 位于主屏左侧或上方的副屏不偏移、不裁断 |
| C-07 | ✅ | 高 DPI 感知 | P0 | Manifest 声明 Per-Monitor V2，遮罩通过物理像素定位 | 100%、125%、150%、175%、200% 下选区坐标正确 |
| C-08 | ✅ | 混合缩放 | P0 | 每个显示器使用独立遮罩窗口，WPF DIP 与图像像素按实际尺寸映射 | 100% 与 150% 混屏跨屏使用时无明显偏移 |
| C-09 | ✅ | 捕获后端抽象 | P0 | `ICaptureService` 隔离调用方；`ResilientCaptureService` 负责后端选择和降级 | 替换后端不修改协调器、选区窗口或输出流程 |
| C-10 | ✅ | GDI 捕获 | P0 | `CreateCompatibleDC`、`CreateCompatibleBitmap`、`BitBlt(SRCCOPY \| CAPTUREBLT)`，所有句柄成对释放 | 普通桌面和窗口可捕获；连续调用不泄漏 GDI 对象 |
| C-11 | ✅ | Windows Graphics Capture | P2 | 无选择器创建显示器/窗口 `GraphicsCaptureItem`，WGC 取帧后转入 SkiaSharp；失败自动回退 GDI | 普通桌面、硬件加速窗口、视频和多数游戏画面可捕获；拒绝或超时不导致应用崩溃 |
| C-12 | ✅ | 鼠标指针开关 | P2 | 设置页控制；GDI 路径使用 `GetCursorInfo`、热点偏移和 `DrawIconEx` 合成 | 开启时指针位置和热点正确，关闭时结果不含指针 |
| C-13 | ✅ | 捕获失败降级 | P0 | WGC 异常、拒绝或超时后尝试 GDI；双后端失败时统一抛出并由控制器提示 | 捕获失败不终止进程；用户收到可理解的错误提示并可重试 |
| C-14 | ✅ | 大图内存与句柄管理 | P0 | 及时释放 COM、D3D、GDI、Skia 对象；提供 `--capture-self-test` | 连续 50 次虚拟桌面捕获自测通过；无持续句柄增长或失控内存增长 |

限制说明：任何常规桌面捕获 API 都不应承诺捕获 DRM 保护视频、安全桌面、锁屏或 UAC 安全提示。WGC 也不是这些场景的绕过手段。

模型管理已接入 U²-Net 轻量、BiRefNet General Lite、Portrait 与 Matting（社区 ONNX 导出），按需下载 3–4 个；设置可指定默认模型、分别保存路径／契约，下载自动配置参数；抠图窗口可切换模型后一键运行。新配置默认 General Lite，旧版单模型迁移保留原默认。Matting 使用 sigmoid 软透明度，General / Portrait 使用配套 sigmoid + min-max。权重不进分发包，不包含 RMBG 非商用权重。框选拖动期间实时预览与真实大模型质量／GPU 兼容性仍待专项验收。

在此基础上新增两个按需高质量下载：BiRefNet General 完整版（973 MB，1024 输入，rembg 固定校验）与 BiRefNet HR Matting（932 MB，2048 输入，PinkPixel 社区 FP32 ONNX，固定版本和 SHA256）。HR Matting 单独使用 `BiRefNetAlpha` 契约，保留图内 sigmoid 的概率输出，不重复激活或拉伸透明度。现有默认模型保持不变；大模型真实质量、耗时及目标 GPU 兼容性仍待专项验收。

托盘“识别粘贴板图片…”先读取并预览图片，再由用户选择 OCR、证件、条码、表格、公式或抠图；不自动执行，翻译需先提取或输入文字。剪贴板使用格式感知读图组件和独立像素快照。

已知风险：HR + DirectML 曾出现内存分配失败和 NVIDIA 原生驱动模块访问冲突。现已将 ONNX 推理放入独立子进程，补上失败会话清理、DXGI 显存预算检查和 GPU 失败后 CPU 回退；超时或取消结束本次进程，GPU 崩溃不再直接终止主进程。每次操作最多缓存四个会话，操作完成即释放，跨请求重载模型会增加延迟。超时仍与 OCR 共用 1–120 秒设置。已通过合成模型的真实 CPU 推理、无效 DirectML 设备回退及杀死子进程后的恢复检查，HR 实际质量、耗时及 NVIDIA 驱动兼容仍待专项验收，不能以这些检查替代真实 GPU 验收。详见[异常与推理隔离](异常与推理隔离.md)。

发布已提供根目录 `publish.bat`，生成独立时间戳目录的 Windows x64 自包含版本，不包含模型和本机配置；分发必须保留整个目录。使用指南改为可独立阅读、复制到博客的纯软件操作教程，不依赖其他文档导航。

长截图手动／自动采集阶段新增持续区域指示框：蓝色边线及四角、四边中点共八个圆形锚点，鼠标穿透且不激活目标窗口；使用系统捕获排除，不可用时改为区外绘制。采集中区域固定，锚点仅定位、不用于拖动调整；完成、取消和失败路径均关闭指示框。离屏多 DPI 渲染已纳入自检，真实多屏滚动与捕获排除待实机验收。

## 推荐路线图

### M1：主流程回归与性能基线

- 完成 T-09 的 `-clip` 实际行为。
- 合并二级栏滑块连续变化产生的撤销记录，并补全不同工具属性回显回归。
- 贴图旋转、输出命名和保存后定位已实现，纳入持续回归，不再列为待开发。
- 建立 Windows 10/11、多 GPU、竖屏和混合 DPI 的回归矩阵。
- 为 N-01、N-02 建立可重复性能基线。

### M2：编辑与历史体验

- 增加 H-02 过滤、H-03 容量/天数清理、H-06 收藏。
- 补充用户数据、异常诊断脱敏与临时录屏残留管理。
- 为历史“再次编辑”设计同时保存原图、标注模板和 schema 版本的容器格式。

### M3：识别与长截图验收

- 竖向长截图入口、裁边和不确定帧手动接缝修正已实现，真实应用兼容性与异常内容继续按竖向样本矩阵验收；横向不承诺、不验收。
- 验证 PaddleOCR／Windows OCR、抠图真实模型与语言包精度；表格／公式已接入模型、解码与导出，继续扩展真实测试集。
- 一键脱敏已接入 OCR、规则及可选本地 Qwen；继续验收漏检、误检与文字范围精度，不将自动检测等同于完整脱敏保证。

### M4：录屏实机验收与后续扩展

- 录屏、音频、摄像头代码已接入，优先验收 10 分钟音画同步、各帧率、设备断开和硬编回退。
- 工作流、通用上传和企业审计尚未实现，应分别评估隐私、许可证、分发体积和维护成本。

## 明确不承诺的能力

- 捕获 DRM 保护视频、安全桌面、锁屏和 UAC 安全提示。
- 绕过目标应用的反截屏或安全策略。
- 在未授权情况下上传截图、OCR 文本、窗口信息或使用遥测。
- 仅凭包版本或代码存在就认定功能达到性能、兼容性或安全验收。
