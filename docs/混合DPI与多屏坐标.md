# 混合 DPI 与多屏坐标

显示器边界、原始截图、鼠标桌面位置和最终裁剪统一使用物理像素。每屏局部 DIP 通过自己的 `DpiX / 96`、`DpiY / 96` 换算到桌面物理坐标，再换算到目标屏局部 DIP。显示器原点保持物理坐标，不将全局原点乘缩放率；尤其不能把来自 `GetCursorPos` 的物理坐标再乘一次当前屏 DPI。

`DisplayMonitorService` 枚举时查询 `GetDpiForMonitor`，失败则尝试 `GetScaleFactorForMonitor`；查询在临时 per-monitor 线程上下文中执行，结束立即恢复。若两者失败则明确标记 DPI 未知并提供 96 DPI 元数据兜底，物理坐标选择不依赖此兜底。`MonitorGeometry` 提供每屏局部 DIP 与桌面像素之间的显式转换。

选区在一张虚拟桌面截图、一个覆盖桌面的 WPF HWND 上完成，替代原先每屏独立遮罩、拖动被起始屏边界截断的路径。单个 HWND 只有一个渲染 DPI，使用 `GetDpiForWindow` 设置尺寸；指针与遮罩 DIP 显式按快照物理边界和实际画布尺寸互换，不通过 `PointFromScreen` 隐式转换。切换鼠标所在显示器时不改变桌面坐标标尺。裁剪分别取整左右、上下边界，避免位置和宽高分别取整导致的边缘偏差。工具条和放大镜约束到真实显示器区域，避开虚拟桌面的空洞。

WGC 与 DXGI 使用统一拼接器，要求每个输出经过旋转归一化后，图像像素宽高与显示器物理边界严格相符，拒绝静默拉伸。多个输出按各自桌面物理原点拼接，显示器之间的空隙填不透明黑色。DXGI 仍在输出所属适配器上创建设备，合成测试中的独立缓冲区不代表实际显卡驱动。

运行自检：

```powershell
dotnet run --project tools/WindowChecks/WindowChecks.csproj -c Release -p:Platform=x64 -- --dpi-only
```

覆盖五档缩放的 25 个有序组合 × 横竖屏 × 正负原点，共 100 组布局；同时验证反向拖动、源/目标屏换算、跨屏选区每条边 ≤1 物理像素、90/180/270° 逐像素旋转、独立输出拼接、跨屏原始像素裁剪，以及五档缩放下的单像素微调。测试使用合成图像，不采集真实桌面。`monitor-dpi.txt` 只记录本机显示器边界与有效 DPI。

## 验收范围

合成自检通过不等于真实混屏验收，N-04/N-05 保持部分完成。需补充 Windows 10/11、100%＋150% 混屏双向拖选、竖屏和 Intel/AMD/NVIDIA 实机矩阵。真实验收使用已知物理坐标的测试图，记录测试日期、提交版本、系统／GPU／显示器布局、拖选起止点与输出四边的像素差，要求每边 ≤1 像素；不要从屏幕显示的 DIP 大小推断裁剪尺寸。
